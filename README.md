## 폴더 구조

```text
hy-wiki/
├── CLAUDE.md          ← AI가 따르는 위키 운영 규칙(결과 설명 시간에 함께 열어 봄)
├── 1부_공통실습/
│   ├── 원자료/        ← 공통 자료(교수자가 작성한 수업용 요약본)
│   ├── 추가자료/      ← 위키 갱신을 체험할 새 자료. 반영 요청 전에는 읽지 않음
│   └── 위키/          ← 공통 위키와 질문/ 폴더가 만들어지는 곳
├── 2부_내위키/
│   ├── 내자료/        ← 내 자료를 복사해 넣는 곳
│   ├── 예비자료/      ← 내 자료가 없을 때 쓰는 연구 현장 AI 쟁점 자료
│   └── 위키/          ← 내 위키와 질문/ 폴더가 만들어지는 곳
└── 완성본_참고/
    ├── 공통_기본위키/  ← 생성이 막혔을 때 복사할 위키(원자료 01~03만 반영)
    └── 공통_갱신위키/  ← 새 자료 반영이 막혔을 때 복사할 위키(추가자료 04까지 반영)와 질문 · 메모 예시
```

- `원자료/`의 공통 자료는 발행기관의 원문이 아니라 수업용 요약본. 중요한 문장은 각 문서에 적힌 원문 경로까지 확인
- `1부_공통실습/위키/`, `2부_내위키/위키/`, `2부_내위키/내자료/`는 원격 저장소에 올라가지 않음(`.gitignore`)

## 내 자료를 넣을 때

- 권장 형식: `.md`, `.txt`, 글자가 선택되는 10쪽 안팎 PDF. 긴 문서는 관련 부분만 발췌해 `.md`로 저장하고 제목 · 저자 · 연도 · 쪽을 함께 적음
- HWP · 스캔 PDF는 변환 시간이 들어 오늘 실습에서는 피함. 필요한 절만 복사해 `.md`로
- 다른 사람의 개인정보 · 공개할 수 없는 자료는 넣지 않음. 파일은 내 컴퓨터에 남지만 읽고 정리하는 처리는 Claude 서버를 거침

```text
완성본_참고/공통_기본위키 폴더의 파일을 1부_공통실습/위키 에 그대로 복사해줘. 다른 파일은 수정하지 마.
```

2) 새 자료 반영 실패 시

```text
완성본_참고/공통_갱신위키 폴더의 파일을 1부_공통실습/위키 에 그대로 복사해줘. 질문 폴더의 기존 파일은 그대로 둬.
```

3) 개인 위키 생성 실패 시

```text
1부_공통실습/위키 폴더의 파일을 2부_내위키/위키 에 복사해줘. 질문 폴더는 비워 둬.
```

| 폴더 | 들어 있는 것 |
|---|---|
| `완성본_참고/공통_기본위키/` | 원자료 01~03만 반영한 위키(목차 · 주제 페이지 · 변경기록). 질문 폴더는 비어 있음 |
| `완성본_참고/공통_갱신위키/` | 추가자료 04까지 반영한 위키와 질문 · 메모 예시(`질문/01_첫질문.md` · `03_메모초안.md` · `04_메모수정.md` · `06_메모갱신.md`) |

- 두 폴더는 빈 사본에서 위 요청문을 차례로 실행해 만든 예시. 페이지 이름과 개수는 내 결과와 다를 수 있음
- 복사가 안 되거나 Claude Code를 쓸 수 없으면 두 폴더의 목차와 관련 페이지를 직접 읽고 원자료와 대조
- Claude Code 실행 불가 시 claude.ai 웹 채팅에 목차 · 관련 페이지 · 해당 원자료를 첨부하고 같은 질문
- 대체 경로로 한 작업을 AI가 자동 생성 · 갱신한 결과로 기록하지 않음
